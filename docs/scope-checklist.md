# 기획서 대비 구현 점검표

기준: `plan/submitted_stage1.json`(1단계 제출 기획서). 상태: 구현 / 일부 / 미구현. "확인"은 화면에서 무엇을 하면 보이는지다. 화면 확인 결과는 `docs/run-log.md`에 적는다.

## 입력

| 항목 | 상태 | 확인 방법 |
|---|---|---|
| 제품 자료 PDF 입력 | 구현 | 1단계 "PDF 올리기" → 문서 목록 위에 "PDF 쪽 색인 중 n/N쪽" → 완료 후 목록에 쪽 수 |
| PPTX는 PDF로 변환해 입력 | 구현(앱 밖 변환) | 앱은 PDF만 받는다. 티링크 자료는 미리 쪽별 텍스트로 만든 `TLINK_DATA_DIR`를 "티링크 자료 불러오기"로 넣는다 |
| 홈페이지 URL(선택) | 구현 | 1단계 URL 칸 또는 "AI 녹취 페이지 넣기"·"설치 사례 페이지 넣기" → 문서 목록에 web 문서(구간 수), 2단계 사진 후보에 URL 사진 |
| 현장 사진 1~5장 | 구현 | 2단계 사진 후보 클릭 또는 "사진 올리기"(긴 변 1,600px로 줄임) |
| 홍보 가이드라인 텍스트(선택) | 구현(자료 폴더의 guideline.json) | 1단계 "홍보 가이드라인" 요약, 4단계 17개 항목 점검표 |

## 흐름 5단계

| 항목 | 상태 | 확인 방법 |
|---|---|---|
| 1. 쪽 단위 색인(문서·쪽 근거 ID) | 구현 | 카드의 근거 표기 "문서명 p.n" / 웹 문서는 "구간 n" |
| 2. 차별점 카드 6~10장(이름, 주장, 비교 대상, 원문 인용과 문서·쪽, 적용 조건) | 구현 | 1단계 "차별점 카드 뽑기" → 카드 보드 |
| 2. 인용문 글자 단위 대조, 없으면 '근거 미확인' | 구현(코드 판정) | 카드의 "원문 일치/근사 일치 n%/근거 미확인" 배지, `bun test` |
| 2. 같은 지표가 문서마다 다르면 '수치 충돌' | 구현 | 주황 "수치 충돌" 배지와 값별 출처 목록 |
| 2. 담당자가 카드를 고치거나 뺀다 | 구현 | 카드 "고치기"(저장 후 원문 다시 대조), "빼기", 체크 해제 시 생성에 안 씀 |
| 2. 충돌 값 선택과 승인 | 구현 | 충돌 상자에서 값 선택 → "승인" → 배지가 "확인"으로 |
| 3. 사진 종류 4가지 판별 | 구현 | 2단계 "사진 판독하기" → 종류 배지 |
| 3. 보이는 것 설명, 관련 카드와 연결 이유 | 구현 | 판독 결과의 "보이는 것", 카드 칩 + 이유 문장 |
| 3. 사진 근거를 문서 근거와 다른 색으로 | 구현 | 초안의 주황 "사진 Pn" 칩 / 파랑 문서 칩 |
| 3. 얼굴·전화번호·간판 노출 경고 | 구현 | 판독 결과의 빨간 "노출 경고" + "확인" 버튼(자동 가림 없음) |
| 4. 블로그 리뷰형 글(추천 구성 5단) | 구현 | 3단계 "초안 만들기" → "네이버 블로그 리뷰형 초안" 탭 |
| 4. 카드뉴스 5장 PNG(1080×1350) | 구현 | "인스타그램 카드뉴스 5장" 탭 → "PNG 5장 내려받기" |
| 4. 설치 사례 짧은 글 | 구현 | "설치 사례 짧은 글" 탭 |
| 4. 문장마다 카드 ID | 구현 | 문장 옆 칩, 칩을 누르면 원문 인용·문서·쪽 팝오버 |
| 5. 근거 칩 | 구현 | 위와 같음, 근거 없는 사실 문장은 회색 "근거 없음" |
| 5. 근거 없음(카드 없는 주장, 원문에 없는 숫자) | 구현(코드 + 모델) | 4단계 경고 목록 |
| 5. 사양 불일치(적용 조건과 어긋남) | 구현(코드 규칙 + 모델) | 4단계 경고 목록 |
| 5. 수치 충돌 | 구현(코드) | 4단계 경고 목록 |
| 5. 가이드라인 누락(필수 키워드·강조 내용·하단 링크) | 구현(키워드·링크·문의처는 코드, 강조 내용은 모델) | 17개 항목 점검표 |
| 5. 숫자·키워드·링크는 코드, 뜻은 생성에 쓰지 않은 다른 회사 모델 | 일부 | 로컬: 생성 DeepSeek, 판정 Claude(다른 회사). 배포본은 다른 회사 키가 없어 DeepSeek 별도 호출(화면에 표시) |
| 5. 경고된 문장만 다시 생성 | 구현 | 4단계 "경고 문장만 다시 쓰기", 원고 검수의 "경고 문장만 제안대로 고치고 다시 검수" |
| 판정 엇갈림 규칙 | 구현 | 한쪽이라도 경고하면 경고, "판정 엇갈림" 배지 |
| 복사와 PNG 내려받기, 승인 뒤 복사 | 구현 | "검수 승인" → 복사 버튼 켜짐 |
| 외부 리뷰 원고 붙여넣기 점검 | 구현 | 4단계 "외부 리뷰 원고 검수", 주소 `/?step=check`로 바로 열림 |

## 기능별 완료 기준

| 기준 | 상태 | 근거 |
|---|---|---|
| 기능 1: 인용문이 모두 서버 대조 통과 또는 '근거 미확인' 표시 | 충족 | run-log 2회차: 10장 모두 exact |
| 기능 1: 학교 도입 수 '200여'와 '150+' 충돌이 카드에 나타남 | 충족 | run-log 2회차 X1 |
| 기능 1: 카드 고치기·빼기 | 충족 | 화면 확인은 run-log에 적는다 |
| 기능 2: 시연 사진 3장이 종류 판별·카드 1장 이상 연결 | 확인 필요 | 화면 실행 후 run-log |
| 기능 2: 사진 근거·문서 근거 다른 색 칩 | 충족 | 주황/파랑 |
| 기능 3: 시연 원고의 틀린 문장 3개 모두 경고, 빠진 필수 키워드 표시 | 충족(API 1회) | run-log: 3/3, '업무자동화' 누락 |
| 검증 계획: 블로그 초안 근거 칩 사람 대조 비율 | 미측정 | 측정 작업이 한다 |
| 검증 계획: 일부러 고친 문장 10개 중 경고 수 | 미측정 | 고정 문장은 마지막 1회만 돌린다 |

## 만들지 않은 것(기획서의 제외 항목과 같음)

SNS·블로그 자동 게시와 예약, 숏폼 영상 렌더링, 성과 측정, 사진 배경 제거·합성·AI 생성 이미지, 사진 자동 가림, PPTX·XLSX 직접 업로드, 여러 회사 계정과 작업 저장, 경쟁 제품 사양 자동 수집.

## 기획서와 다른 점

- 모델: 기획서는 Claude Opus 5.5(추출·판독·생성) + Gemini 4 Argon(판정). 실제는 DeepSeek V4.1 Flash(추출·판독·생성) + 로컬 Claude Opus 5.5 CLI(판정). Gemini·Claude API 키가 없어서다.
- 자동 실행 버튼을 더했다(같은 단계 함수를 순서대로 부른다).
