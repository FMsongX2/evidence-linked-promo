## 오경고 원인(baseline 실제 출력으로 확인)

1. **근거를 카드에서만 찾았다.** 카드 10장에 없는 사실(퀵 버튼 저장 위치, 통화 목록 7일, 080 수신거부, 지원 브라우저, 재생 속도, 기업광랜 요금, 당겨받기 조건)은 바른 문장이어도 코드가 "근거 카드가 연결되지 않은 사실 문장", 모델이 "연결된 근거가 없습니다"로 경고했다(W04·W06·W07·W08·W12·W13·W14·W16·W19).
2. **모델에게 근거 원문을 짧게만 줬다.** 판정 모델은 카드 인용 1~2문장만 봤다. 같은 쪽에 있는 내용(STT 자동 시작, PDF 공유, 실제 통화로 만든 교육자료)을 "인용에 없다"고 경고했다(W05·W15·W18). 프롬프트의 unsupported 정의("원문 인용에 없는 내용")가 이 방향으로 기울게 했다.
3. **숫자를 문서·카드 전체에서 대조했다.** '700석'(IVY)을 같은 카드의 '3,000석'(한국전력)과, '1,000 USER'(세종텔레콤)를 '3,000'(최대 구축 규모)과 비교해 수치 충돌로 잘못 경고했다(W01·W03). 카드에 없는 수치는 문서 전체에서 같은 숫자를 찾아 "원문에는 있습니다: p.○"라고 다른 맥락의 쪽을 댔다(W08 '7일', W10 '5건', W14 '2'). 전화 앞자리 '080'도 수치로 봤다(W16).
4. 적용 조건 필드가 비어서 생긴 오경고는 없었다. 조건 누락 고친 문장 8개 중 4개는 카드 조건이 없어 '근거 없음'으로만 잡혔다(종류 불일치).

## 바꾼 것

1. **근거 쪽 검색(코드, `src/lib/retrieve.ts`)**: 쪽 텍스트를 줄 단위 구간(약 220자)으로 나눠 글자 바이그램 BM25로 문장마다 상위 3쪽을 고른다. 원고 문장 근거 연결(DeepSeek 호출 1회)은 없앴다. 후보 카드도 바이그램 겹침으로 코드가 고른다.
2. **교차 판정 질문을 좁혔다(`JUDGE_SYSTEM`)**: 근거 쪽 전체 텍스트를 보여 주고, verdict를 supported / contradicted / condition-omitted / not-in-sources / not-factual 로 나눴다. 경고는 어긋나는 원문 구절(sourceQuote, sourcePage)이나 문장 속 없는 요소(sentencePart)를 그대로 인용할 때만 하게 했다. "의심스럽다는 이유만으로 경고하지 않는다", "요약·표현 바꿈은 supported".
3. **모델 경고를 코드로 대조(`pipeline.ts`)**: sourceQuote가 그 쪽(또는 그 문장의 다른 근거 쪽) 텍스트와 대조되지 않으면 경고에서 빼고 `reviews`("확인 필요")로 낮춘다. not-in-sources는 sentencePart가 문장에 있어야 하고, 코드가 그 구절을 원문에서 찾으면 역시 `reviews`로 낮춘다. 코드 경고와 같은 종류의 모델 경고는 하나로 합치고 `agreed` 표시.
4. **숫자 대조 범위(`check.ts`)**: 문장의 근거 쪽(모델 인용 쪽 + 검색 상위 3쪽 + 연결 카드 인용) 안에서, 숫자 앞뒤 20자 맥락이 문장과 겹치는(바이그램 겹침 0.35 이상) 수치끼리만 같다/다르다를 판정한다. 같은 맥락이 없으면 "같은 맥락의 수치를 찾지 못함"으로만 쓰고 다른 쪽을 근거로 대지 않는다. 0으로 시작하는 번호 앞자리(080, 070)는 수치에서 뺀다. 단위가 한쪽에만 있으면(3.5만/월 ↔ 3.5만원) 값으로 비교.
5. **숫자 맥락에 '원문 줄' 겹침 추가**: 표의 짧은 줄은 앞뒤 20자 창이 다른 칸을 섞어 겹침이 낮았다(W14 '0.5배' ↔ "재생 속도(0.5x~2.0x)"). 문장과 그 수치가 든 원문 줄의 겹침이 0.35 이상이어도 같은 맥락으로 본다. 모델 인용이 대조를 통과한 문장(뒷받침이든 어긋남이든)은 '근거 없는 문장'으로 보지 않는다.
6. **단정 표현 규칙 일반화**: 보편 양화 표현(어떤/어느 ~든·~에서도, 제한·상관·관계·예외 없이)을 단정 표현 목록에 더하고, 연결 카드의 조건뿐 아니라 근거 쪽의 조건 줄(~에서만, ~에 따라, 제한, 미만, ~해야, 참고:)이 문장과 겹치면 사양 불일치로 본다. 특정 문장의 낱말은 넣지 않았다.

## 속도

- 원고 점검: 근거 연결 호출 제거, 교차 판정을 5문장 묶음으로 나눠 동시 호출(40문장 = 8묶음), 강조 내용 판정은 별도 호출로 같은 시간에, 고쳐 쓴 제안은 판정 모델의 fix를 쓰고 fix가 없는 경고 문장만 그 문장의 근거 쪽만 담아 3문장 묶음으로 동시에 생성 모델 호출. 162.6초 → 20.9~22.4초(같은 40문장, 캐시 끔). 가장 긴 호출은 강조 내용 판정(40문장 원고 전체를 읽음)이다.

## 남은 문제

- 종류 불일치 1건(c2·c3 세 번 모두 같음): V17(비교 대상 바꾸기, 기대 '근거 없음')을 교차 판정이 원문 "보고서로 바꿔주는 곳은 드뭅니다"를 인용해 '사양 불일치'로 잡았다. 경고는 떴다.
- 숫자 맥락 임계값 0.35와 검색 상위 3쪽은 devset으로만 확인했다. 표가 많은 자료에서 같은 줄에 여러 지표가 있으면(예: 500M·100M 요금) 코드는 구분하지 못하고 교차 판정에 기댄다(V04는 모델이 잡음).
- 판정 엇갈림(한쪽만 경고)이 12~13건이다. 대부분 모델만 잡은 조건 누락·없는 기능 문장이다.
