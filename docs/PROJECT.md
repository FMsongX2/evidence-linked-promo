근거 달린 홍보문은 티링크 제품 자료와 현장 사진으로 홍보 초안을 자동으로 만들고, 문장마다 원문 근거를 대조해 사양과 다른 문장을 게시 전에 걸러 내는, 티링크 홍보 담당자와 외부 리뷰 작성자를 위한 웹 앱입니다. 담당자는 홍보 글을 AI로 쓰면 5분 정도지만 실제로는 30분~1시간이 걸린다고 답했습니다. 같은 문장 20개를 참가자와 담당자가 제품 자료와 대조하는 데는 40분 이상 걸렸고, 이 앱은 같은 20개를 18.3초에 점검했습니다.
1. 기획서 기능 3개의 구현과 완료 기준
(1) 차별점 카드 보드: 자료 5종 113쪽에서 원문 인용·문서·쪽·적용 조건이 붙은 카드 10장을 뽑았고, 인용 23개가 모두 서버 글자 대조에서 원문과 일치했습니다. 학교 도입 수 '200여'(회사소개서·제안서)와 '150+'(설치 사례 페이지)를 수치 충돌로 표시하고, 담당자가 값을 골라 승인하거나 카드를 고치고 뺍니다. 완료 기준(인용 대조·충돌 표시·카드 수정)을 충족했습니다.
(2) 현장 사진 판독: 티링크가 지정한 설치 사례 사진의 종류와 보이는 것을 적고 카드에 연결 이유와 함께 잇습니다. 사진 근거는 주황, 문서 근거는 파랑 칩으로 나뉘고, 전화번호 등은 노출 경고를 띄웁니다.
(3) 생성과 게시 전 점검: 블로그 초안, 카드뉴스 5장 PNG, 설치 사례 글을 만들고 문장마다 근거 칩을 붙입니다. 경고 4종(근거 없음·사양 불일치·수치 충돌·가이드라인 누락), 가이드라인 17개 항목 점검표, 외부 원고 검수, 경고 문장 다시 쓰기, 승인 후 복사를 갖췄습니다. 시연 원고의 틀린 문장 3개 중 3개를 경고하고 빠진 필수 키워드를 표시해 완료 기준을 충족했습니다.
계획에 없던 공개 데모와 자동 실행을 더했습니다. 자동 실행 1회는 입력부터 점검 끝난 초안까지 236.1초, 모델 호출 12회, 토큰 입력 136,210·출력 51,308입니다.
2. 측정 결과(후원사 실제 자료·가이드라인)
(1) 실제 사양을 고쳐 만든 문장 10개(앱 실행 전 고정, 규칙 조정에 안 씀)를 한 번 점검해 10개를 경고했습니다(기획서 목표 8개 이상). 숫자 변조 2/2, 조건 누락 4/4, 없는 기능 2/2, 비교 대상 2/2이고, 경고 종류까지 맞은 것은 9개입니다. 바르게 쓴 짝 문장 10개의 오경고는 0개입니다.
(2) 블로그 초안의 사실 문장 19개를 생성 모델과 다른 모델로 별도 대조하니 원문이 뒷받침 14, 부분 2, 뒷받침 안 됨 2(둘 다 앱이 경고), 사진 문장 1이었습니다.
3. 판정 방식
숫자·키워드·링크는 코드가 대조하고, 주장과 인용의 뜻은 생성에 쓰지 않은 다른 회사 모델이 판정합니다. 모델은 어긋나는 원문 구절을 인용할 때만 경고하고, 그 구절이 원문에 없으면 코드가 '확인 필요'로 낮춥니다. 코드와 모델 중 한쪽만 경고해도 경고로 띄우고 "판정 엇갈림"을 표시합니다. 인용문은 공백·구두점을 지우고 포함·근사 일치로 대조하며, 실패하면 '근거 미확인'으로 남깁니다. PDF를 직접 올리면 쪽 단위로 색인합니다. 시연과 측정에는 미리 쪽 단위로 뽑아 둔 같은 자료 5종과 설치 사례 페이지를 썼고, 글자가 빈 쪽은 0쪽입니다.
